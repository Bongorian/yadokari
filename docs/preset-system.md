# Presets, kits and track names (MGXC13)

The container format is MGXC13. Files in older formats are rejected with a clear error; there is no migration reader and no automatic deletion. The GUID / revision / CRC contract is specified below. The in-song pool holds 256 slots.

Preset output trim is stored as the optional PTRM v1. Content without a PTRM reads as unity gain; the trim is preserved on user saves independently of INCLUDE FX, and Track LEVEL keeps the value of the mount destination.

## Design decisions

- A GUID is 128 bits and a revision is a non-zero uint32. Factory GUIDs are fixed by the manifest, and the user GUID namespace is separate. A display name or a save path is not identity.
- The in-song pool folds the same GUID/revision into one slot. Different content under the same identity is never silently swapped in. An edited Track is an independent working copy, and the song stores its values as well. Library resolution does not overwrite a Track's saved edits or FX.
- An asset path is a hint. On a CRC mismatch, resolution falls back to the shelf index; if the asset is not found, the CRC is reported and the entire mount is held. Indexing and I/O run only on the file-service side.
- A Track name is independent of the sound name and does not change when the sound is exchanged or previewed. It is saved as the optional TNAM chunk inside TRCK.
- A change of name or asset path alone is not a change of sound content. A duplicate kept as a distinct object carries a new GUID and provenance.
- A Kit holds no phrases; it is the ENGN of a single DrumKit. The fixed IDs of the 16 built-in sounds, the basic 3 Kits and the debug content are recorded in `builtins` and `builtin_factory_identity` of the [fixed assignments](../assets/factory-library/identities.json).

## Behavior and operations

- A Track that has only been edited directly in ENGINE can be saved as an anonymous working sound. It is registered into the pool only on file mount, on a named save, or on an explicit STORE; the 16 slots are not filled automatically. Re-mounting the same GUID/revision reuses the existing slot, and the same GUID/revision with different content is rejected. An old revision is not silently overwritten.
- The library is verified for exact agreement with the Song's embedded definitions. Because the normalized content after CRC resolution is identical, the embedded asset numbers can be kept, and a separately saved Track working copy is not overwritten. If an external version cannot be read or does not exist, the embedded definition is used; a newer revision alone is never substituted. The normal status field shows `NEW REV` / `EMBEDDED`, and warnings such as audio faults take priority.
- Content comparison passes the engine's canonical encode, plus Layer, plus optional FX, plus a non-unity output trim, into SHA-256. Names, GUIDs, provenance and paths are excluded, and asset numbers are normalized by CRC/root/BPM. WaveRing preserves the relative position of waveform numbers and the empty fallback. An asset CRC identifies the asset; the MGXC body CRC detects corruption; the two are never confused.
- The entry points and terminology for sound selection follow the UI organization. BROWSER is dedicated to the file shelves. ENGINE shows the sound list of the selected engine, and a 4-D press descends into the standalone PRESETS / KITS. The performance-face Top5 uses the same list. SELECT + 4-D left/right steps through the current kind.
- The standalone list uses KIND × ENGINE × ORIGIN. Top1 is KIND, Top2 ORIGIN, Top3 PREV, Top4 NEXT; on the right, Top5 is PREVIEW, Top6 LOAD, Top7 FILES, Top8 BACK. K1 selects, K2 chooses the target Track, K3 ENGINE, K4 ORIGIN. Entering, moving within, and filtering the list are silent and do not start decoding originals or loading assets. Preview starts only when Top5 PREVIEW is pressed, and stops on movement. A preview does not register into the pool; only LOAD registers the canonical sound and mounts it as the working sound. History also restores the list filter and the cursor position within the window.
- SELECT + 4-D press, or SHIFT + Top5 STORE FILE in the list, saves to User. A Factory sound can be saved derivatively into the User shelf under the same GUID. SHIFT + Top6 STORE AS opens name entry; SHIFT + Top7 DUPLICATE creates a new GUID. When a normal STORE AS renames a User sound, the old name is removed after the new file has been verified. Name entry uses K3 INCLUDE FX / K4 DUPLICATE; the warnings on failure to remove the old name, and the save identity / CRC / unknown-data preservation, follow the existing contract.
- A track name is edited at SYNTH SHIFT + Top6 TRACK NAME. MIXER Top6 is dedicated to [TWIN](twin.md). A blank name returns to the sound/instrument name. Changes, and Track Name import from SMF, are Undo targets. SMF adopts the first named MTrk that contains the selected MIDI channel, replaces non-ASCII characters with `?`, and truncates at 95 characters. An SMF without a name leaves the current name unchanged.
- In the Browser, a file in an older format is shown as `UNSUPPORTED`. Individual deletion is possible after confirming with the existing DELETE on the SHIFT side. The current song, Factory and operational files, and anything being previewed are protected and are never deleted automatically.

## Ownership model

- `PresetRegistration` is the canonical registration into the pool; `TrackInstall` is the operation that publishes the working sound, lane kind and asset references together; `AssetClonePlan` is an aliased reference to an existing PCM view. The three roles are kept separate. Mounting and merely updating a saved identity are also separate operations.
- The identity of an asset entity is its CRC. ROOT / BPM are playback interpretation and are not included in sound-content comparison. When another Track / the pool / a phrase / audio references the same binding, only the selected working sound branches to a separate binding. PCM is not duplicated; the existing immutable view is shared, and the DSP swaps the reference and metadata in a single transaction. Undo/Redo changes neither the canonical sound nor other Tracks. If no slot is free, the original sound is kept and the operation is rejected.
- Favourite is a per-CRC UI attribute and is separated from the ROOT / BPM update operation. Undoing a Favourite does not roll back playback metadata.
- The bytes of an unknown ENGN child / Preset root / Preset TRCK / Song SND are kept in the file owner's immutable record. Only runtime cookies are carried by the working copy, the pool and Undo. Just before saving, the sidecar is composed from the current cookie, which prevents unknown data of another sound from mixing in on slot reuse or Undo. Unknown metadata of a Song Track still belongs to the Track itself and is not exported into a Preset.
- `PUNK` is an optional v1 chunk that preserves the original parent scope. The [format specification](project-format.md) defines the arrays of the 3 streams. Cookies are not saved. The storage cap for unknown bytes is 2048 definitions / 8 MiB, and the previous generation is released on a Project exchange. If allocation or the cap fails, the mount is not published.
- The storage graph for unknown data also counts duplicate references toward the 8 MiB, and the check is made before mounting and before copy allocation. Unpublished records for a failed mount are discarded, and identical extension data shares an immutable record.
- Replacing an in-use pool entry via STORE is rejected. Even if a mount is undone, a canonical sound that another Track or phrase referenced later remains. An uninterpreted future SND is not overwritten by STORE.
- Changing the ENGINE kind, or assigning a WAV to a different kind of sound source, restores the working sound — including provenance, unknown fields and Morph — from the Undo snapshot. A direct RECALL of a pool sound also connects to the slot matching its identity.
- Circle's SessionFiles and the large file-scope sidecar tables are placed on the heap. Rendering only copies cookies and reference values and performs no allocation, I/O or lookup of unknown bytes.
- The CRC index scan stops as soon as a matching entity is found. Known-mismatch rows are excluded from the first search, but if nothing is found a re-hash always takes place, so an overwrite with the same size and timestamp cannot override the truth of the CRC. Partial indexes are reused, and hidden / operational directories are not scanned.

## Additional sampler GUID assignments

The fixed identity ledger holds 115 entries, including twelve designated sampler GUIDs and the builtins. `pending_factory_import` separates registration from inclusion, and the packer rejects a missing original other than one that is not yet included. A GUID is an opaque 128-bit value; the leading `f0` of Factory GUIDs is an allocation convention, not a constraint of the codec.

## Mount boundary for registered engines

Normal Song / Preset / Kit loading and preview in [SessionFiles](../src/session_files.h) verify the registration of the Track, the pool, Layer children, the Morph bank and parameter owners. If an unregistered engine is present, mounting is rejected with `Unsupported engine / current content kept`, and the Project, sounds and generation are preserved. A removed sound source is never replaced by a similar one. The low-level codec preserves unknown payloads for inspection and round trips, but that success is not treated as a mount that can sound.

For additional drums derived from current engines, see the [factory library](factory-library.md). Standalone native Presets and baked Sampler Kits are kept separate, and the generation source is included in the name.
